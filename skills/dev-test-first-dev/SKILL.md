# 测试先行开发工作流

1. **标准流程**：先写测试（红）→ 最小实现（绿）→ 全量回归（`go test -race -count=1 ./...`）→ 验证后 git push
2. **开发纪律**：任何疑问先确认不擅断（设计文档未覆盖/冲突点先给选项确认，文档内部矛盾要报告）；所有命令带 `timeout N`；验证用 /tmp 自建小示例（秒级），大仓库仅最终验收
3. **断言数值区分新旧行为**：契约变更第一步改写断言——"分组新增恰好 7 个节点"（多一个即越界），而非"节点变多"
4. **负例优先 + 形态矩阵**：识别类需求先写"不应识别"的负例；按起点×传递×写入枚举变体（维度按指令全集系统枚举，不凭经验）；功能分两层验证（展示层 + 数据流贯通层）；代码里"无法/跳过/不支持"注释不当事实——都要问"其实能不能？"
5. **最小复现 bug 报告**：完整最小复现 + 精确根因（文件:行号 + 原因 + 优先级） + 预期行为
6. **复杂需求先设计树访谈**：编号问题 + 推荐答案 → 用户一行拍板 → 决策落档后实施

坑：单测全绿 ≠ 真实可用（见 dev-verify-and-accept）；fixture 行号别手数（用解析器动态取或存在性断言）；mock 要与真实形态对齐。
