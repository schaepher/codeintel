# 根因链式排查与根治

1. **根因链式排查**：从表象逐层往下找根因（修机制层不修输出过滤层）；把"抓取错误"与"真缺失"分离后再归因
2. **先验证根因再动手**：报 bug 必须附根因证据（定义位置/上下文行/触发路径），确认后才动代码——防基于误判（正则误匹配）的错误修复
3. **同类 bug ≥2 次即根治**：换该领域专用开源库或写脚本根治，禁止继续打补丁；根治手段必须固化（依赖入库/脚本进仓库 + 加入交付检查项）
4. **举一反三扩散排查**：单点修复后按形态矩阵扩展排查全部变体，全项目搜同类使用点
5. **结构化编辑**：代码变换走 go/ast 工具（如 dev-line-limit 的 asttool）或唯一锚点精确替换，禁用正则/sed 盲改；批量替换断言"恰好命中 1 次"并核对 diff；每次大改后立即编译再继续
