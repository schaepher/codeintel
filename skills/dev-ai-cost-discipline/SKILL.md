# AI 成本与工具纪律护栏

真实 AI 调用是成本中心：一次失控的全量调用就可能耗尽额度；工具连续
失败仍不降级会浪费大量调用。本 skill 规定调用前的预算纪律与执行中的
工具纪律。

## 一、AI 调用成本预算（三段式）

```
1. 声明预算：调用前明确"预计 N 次、预算 X"
2. 单条验证：用 fake CLI/--dry-run/单条数据先跑通
3. 全量仅一次：验证 OK 后才全量跑，且只跑一次
```

配套：
- **批量优先 + 同会话 resume**：把分散的 AI 需求先清单化收集，合并成
  一次请求；上下文通过 resume/session_id 传递，后续轮次不重复付
  token 费。实证：批量合并一次调用即可完成全部条目，逐条调用超时
  失败率高
- 分批是"确有必要的降级手段"，不是默认形态；用户说"实在有必要才分
  两次"时，应主动确认度量维度（条数 vs prompt token 大小）——大批量
  场景真正的约束是 token 上限而非条数

## 二、工具纪律硬规则

1. **工具白名单**：系统提示写明可用工具名——不得虚构不存在的工具名
2. **自包含任务禁止查库**：任务信息已全在提示词内则禁止调用查询类
   工具
3. **连续失败 2 次即降级**：尤其 `echo hello` 都失败时判定环境不可用，
   基于已有信息直接输出并标注置信度；**失败信息只记日志，不得作为
   回复正文**（曾把环境错误提示当回复正文，导致请求零产出）
4. **路径预检**：引用文件必须位于工作目录内（外部文件先 cp 进目录），
   不可读时直接上报原因不编造（读不到文件时拒绝编造、给替代解法）

## 三、子代理/后台任务管理

- 批量启动子代理前先声明数量与理由，避免额度失控；用户叫停时立即
  停止
- 后台任务先声明再启动；收尾状态见 dev-crystallize-knowledge 四要素

## 四、降级路径模板

```
工具/环境不可用：如实声明 → 列出可替代通道（按成本排序）→ 基于已有
信息输出结果并标注置信度 → 承诺条件恢复后补齐。
```

权限/环境问题跨会话重演时，第一次就应落档（见 dev-crystallize-knowledge）
并降级，而不是反复重试。

## 已知坑

- 空响应后**缩小粒度重试**而非原样重发（见 dev-prompting-playbook）
- 全量跑之前先确认"这次是否有真实收益"——用户只要结论时，直接给结论
  不重新跑
- 大仓库验证消耗大——定位/验证用秒级小 fixture，真实仓库只用于最终
  验收（见 dev-verify-and-accept）
