# 交付验证与验收门禁

"测试全绿" ≠ "用户可用"——"已发送但不可见"类交付（渲染失败、空图、字段错位）都源于"断言全绿但产物/渲染行为错"。

1. **交付前真实自检**：真实打开/渲染/测量（像素/坐标/DOM）；以用户视角通读关键区块（能渲染吗？数据空吗？字段对吗？）；交付附带可打开产物 + 核对清单，不只发"全绿"结论
2. **双向核对**：源码→产物遗漏检查 + 产物→源码幽灵检查（逐一比对）；worktree 对比"改前 vs 改后全量一致"确认无回归
3. **全量穷举**：可穷举产物全量比对不抽样；验证工具自身判据逐轮校正；报 bug 必须附根因证据（位置/上下文行/触发路径），防基于误判的修复
4. **真实大仓库验收 + A/B 对照**：重建基线 → 对照组/实验组双份交付 → 按固定问题对比（哪里不对？如何改进？新增能力杠杆在哪？）→ 优化方案
5. **性能数字验收**：优化前后耗时/倍数对比（先测量拆解再动手；实测无收益即回滚）
