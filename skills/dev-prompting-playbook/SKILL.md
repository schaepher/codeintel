# 封闭式提示词打法（生成型批量任务）

从大量生成型会话复盘沉淀：**"高质量提示词 → 单轮命中"**是批量任务
的常态（44/44 个有 AI 回复的批量片段全部单轮闭环、零返工）。

## 一、六要素一次性打包（缺一不可）

一条用户消息内同时给出：

| 要素 | 内容 | 示例 |
|---|---|---|
| 1. 任务 | 明确动作（写别名/描述/划分域） | "为以下数据库表写中文别名" |
| 2. 业务语义 | 一句话锚定语义方向（防字面翻译） | "业务语义，<=10 字" |
| 3. 量化约束 | 可机检的硬指标 | "每表一个，<=10 字"、"每列一句话 <=30 字"、"识别 3-8 个术语" |
| 4. 封闭清单 | 表名+全部列名/符号一次给全（输入自足） | "表名: nodes 列: file_path, id, kind, ..." |
| 5. 输出格式 | "只输出 YAML"、"只输出 JSON" | "只输出 YAML:" |
| 6. 模板 | 占位符模板锁死结构 + 缺省省略规则 | "alias: <中文别名>"、"缺哪个部分就省略哪个" |

**效果**：AI 零追问、首答即终稿、输出可直接被脚本消费。

## 二、输出格式硬约束（最高频失误点）

- 显式追加 **"不要 Markdown 代码围栏、直接输出纯文本"**——这是被报告
  最多的执行缺口（格式偏差约 24% 的错误率）
- 模板用占位符：`alias: <中文别名>`、`- name: <列名>\n  comment: <说明>`
- 预定义空数据行为："缺哪个部分就省略哪个"（无事实时省略对应段，勿编造）
- 量化口径要写死："中文按字、ASCII 按词、空格不计"，否则出现
  "31 vs 30 无法判定"的歧义

## 三、反幻觉三件套（危害最高的错误源）

1. **先读真值再作答**：注释/命名/描述类任务，先 Read 权威文件（DDL/
   domain-facts/导出 JSON）再回答——先查 schema 的会话是全批最成功样本
2. **事实编号白名单**：给输入事实编号（F1、F2…），禁止引用未提供的
   编号/概念（"文件里没有的包路径、表名、服务名一律不要写"）
3. **推测显式标注**：无法证实语义时强制标 `[推测]`/`（待确认）`，并附
   1~2 行样例数据压缩猜测空间

配套约束："包与表只归属一个域"、"覆盖文件中的全部包与表（未覆盖的
会丢失归属）"——实测可达 15/15 包、11/11 表全覆盖、零虚构。

## 四、大请求分批 + 小样验收 + 缩小粒度重试

- 列说明类：按业务域每批 ≤10~15 张表（别名类可 50+ 张）；先 3~5 张
  验证格式再全量
- 失败后**缩小粒度重试**（60 表整批失败 → 单表成功），不要原样重发；
  空响应后下一轮显式写"从 XX 开始继续，只输出未生成部分"
- 预估超限时按 modules→tables→glossary 顺序截断并标注"未完，待续"
- 真实 AI 调用前先跑 3-5 个校准样本（见 ai-cost-discipline）

## 五、下游程序化校验闭环（把 AI 自检升级为管道强校验）

脚本断言：YAML 可 `yaml.safe_load` 解析、无代码围栏、字数 ≤N、
输出 name 集合与输入清单差集为空、术语数量在界内；失败自动重试或
告警。参考实现（Python）：

```python
import yaml, sys
out = sys.stdin.read()
assert not out.startswith("```"), "含代码围栏"
data = yaml.safe_load(out)
names = {item["name"] for item in data}
assert names == EXPECTED_NAMES, f"差集: {EXPECTED_NAMES - names}"
```

## 已知坑

- 输出模板**单数与输入清单数量错位**会引发"只答一部分"（模板写
  `alias:` 单数、输入却给 N 列）——多实体任务显式声明"共 N 行"
- 别让 AI 当"推理器"；输入封闭清单后它是"转译器"——调用者数为 0
  直接支撑"测试桩/入口"判断
- 术语表一次性定稿并锁定为引用物（见 crystallize-knowledge），防
  跨会话口径漂移
