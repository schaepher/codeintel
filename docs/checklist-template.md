# Checklist / 新任务模板（todo30–33 教训固化）

用途：写新 todo 文档或交付 Checklist 时直接套用。**示例通过只能标“部分”**；
每条「实现要求 / 独立验收」必须有正例与反例测试证据。

## 1. Checklist 表（交付时逐项填写）

| # | 原子要求（引用文档条款） | 实现要点（身份/位置/绑定） | 正例测试 | 反例测试（改一个事实即失效） | 状态 | 证据（命令/JSON） |
| --- | --- | --- | --- | --- | --- | --- |
| X | 例：提交证明必须绑定同一事务声明 | 声明偏移/失败路径；禁止任意 Commit | … | 另一事务/条件 Commit/忽略错误 | 完成/部分/未开始 | … |

状态定义：

- **完成**：该编号全部「实现要求」与「独立验收」都有对应正例 + 反例测试，且
  真实源码 → init → CLI 通过。
- **部分**：只覆盖公开示例或部分变体；必须列出**剩余变体清单**，不得隐藏。
- **未开始**：没有生产实现或没有验收证据。

## 2. 新任务编写强制项

每个编号至少写清：

1. **原子输入**：源码/夹具、仓库形态（单 module/多 module/子目录包）、前置事实。
2. **可复现命令**：完整 CLI（含 init、query、jq 过滤器）；修改前输出原文。
3. **预期输出**：正例的完整 JSON/文本/图契约。
4. **反例矩阵**：至少覆盖“改一个事实就失效”（身份、顺序、位置、绑定、预算、
   解析、跨文件/跨包、遮蔽/别名、条件分支）。
5. **禁止捷径**：明确写出本项不允许的实现方式（对应文档「不能按…」条款）。
6. **预算与失败语义**：超限/取消/非法参数是失败、partial 还是 unknown，必须写清。

写新任务前先读上一轮 Checklist 的「明确边界 / 未覆盖」；上一轮未覆盖的变体
默认进入新任务，除非明确判定不需要。

## 3. 上一轮漏点复查表（写新任务时逐项回答）

| 检查点 | 禁止的实现 | 应采用的身份/证据 |
| --- | --- | --- |
| 声明身份 | `pkgVars[id.Name]`、短名集合 | AST `*ast.Object` / 声明偏移 / 文件+导入+导出名 |
| 执行位置 | 全函数 `mutated` 标志、任意 Commit/return | 语句/调用点偏移、入口树 path、可达分支、静态排除 |
| 事务/资源绑定 | 按变量名/方法短名/err 前缀 | Begin→写入→Commit 同一事务声明；source_id+snapshot_hash 一致 |
| 字段/读取身份 | 同名即同对象、只看 kind/symbol/参数下标 | type_id + 字段路径 + 根身份 + 声明位置 |
| 跨文件/跨包 | 只解析当前文件、同名回退 | 包内文件索引、import path、真实声明 |
| 预算时机 | 先 append 结果再检查、超限后用部分状态 | 加入前检查；超限 partial 且不借用部分证明 |
| 完整解析 | `Sscanf("%d")`、只解析前缀 | 整串消费；拒绝后缀/零/负值/溢出；执行前校验 |
| 完整流程 | 只导出根入口树、逐组合重置预算 | 完整 workflow（入口/连接/实例/前端/图）；共享预算 |
| 反例 | 只测正例/只断言非空 | 每个否定条款至少一个失败测试 |

## 4. 提交前自检

```sh
scripts/verify.sh --quick
scripts/verify.sh                 # -race 14 包基线
PATH="$(go env GOPATH)/bin:$PATH" go test -tags integration ./integration -count=1
```

- grep 反捷径模式（见上表「禁止的实现」）；命中即补测试或改实现。
- Checklist 证据逐条引用“要求编号 + 测试名 + 实际输出”，不只写“已通过”。
- 真实业务验收（如 28 流程）必须由调用方源码完成，公开示例只能证明机制。
